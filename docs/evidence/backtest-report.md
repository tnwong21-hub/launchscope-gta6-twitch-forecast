# RAMQE Backtest Report — LaunchScope (local research, not an official grade)

Generated by `repo/tools/backtest.ts` from the official dev-kit comparables. **No practice
target answers exist in the kit; nothing here is an official make.fun score, final grade,
prize, leaderboard rank, or top-rank claim.** The four practice launches (p00–p03) are
absent from the comparables list and their withheld targets are never used as labels,
features, or tuning signals. All metrics below are reproducible local experiments on the
supplied comparable launches only, and all configuration was chosen in-sample.

## Reproducing these numbers

```bash
node tools/backtest.ts /path/to/p00.in /tmp/launchscope-backtest.json
npm run backtest -- /path/to/p00.in /tmp/launchscope-backtest.json
npm run backtest:help
```

The tool prints one table per protocol and writes full per-case records to the JSON
report. It requires an explicit input path; with no arguments it prints a usage error
rather than guessing a file.

## Protocol

### LOCO — leave-one-comparable-out (the published benchmark)

- 37 usable comparable launches. The 38th, the GTA6 prelaunch category, has no
  release-day hour-1 anchor and is excluded from ratio curves.
- For each launch `c`: cut its own curve at hour 1 (hide hours 2–24), forecast from
  **all other 36** comparables, then score hours 2–24 against `c`'s actual viewers. **No
  release-date filter** is applied here — this is the exact protocol that produced the
  published benchmark.
- "Rolling subset" = the 11 clean rolling-midnight console launches — the regime matching
  all four practice launches and GTA6. "All" = all 37 usable comparables.

### TEMPORAL — strictly prequential temporal holdout (robustness check)

- Comparables are sorted by `day_start`. The pseudo-case for launch `i` may use **only**
  launches strictly earlier than `i`. The date gate is applied explicitly, per
  pseudo-case, inside the backtest itself — it is never enabled in the shipped production
  config (`maxDayStartMs = Infinity`).
- The first six launches are skipped as warm-up (too few predecessors for a fair
  comparison).
- Nothing from the future is consulted. This protocol is a robustness check, **not** the
  published score; it is intentionally harsher because early launches have few analogues.

### Scoring

Exact competition log pinball loss: mean over all (hour, level) items of
`2*max(tau*d, (tau-1)*d)`, where `d = ln(max(1,y)) - ln(q)` and `q` is the forecast
quantile. Lower is better. Also reported: typical |log| miss % and empirical 90%
interval coverage (`q05 <= y <= q95`). A row whose `q` vector is not exactly five
elements is skipped — which is why the five-element `Z` regression guard matters.

## Headline anchors (exact, independently verified)

| Protocol | Forecast | Loss (all 37) | Miss % | Cov90 | Loss (rolling 11) | Miss % | Cov90 |
|---|---|---:|---:|---:|---:|---:|---:|
| LOCO | House baseline (persistence) | 0.929650 | 213.3 | 0.624 | 0.363046 | 73.6 | 0.802 |
| LOCO | **RAMQE-1.0.0 (production)** | **0.395114** | 82.1 | 0.908 | **0.251989** | 43.2 | 0.901 |
| Temporal | House baseline (persistence) | 1.049189 | 256.8 | 0.589 | 0.413219 | 87.3 | 0.766 |
| Temporal | **RAMQE-1.0.0 (production)** | **0.537588** | 111.6 | 0.767 | 0.304398 | 54.5 | 0.777 |

On the target-relevant rolling-midnight regime under LOCO, RAMQE cuts log pinball loss by
about 31% versus the house baseline (0.252 vs 0.363) and typical miss from 73.6% to 43.2%,
with 90% coverage near the nominal 0.90. The harsher temporal holdout still beats the
house baseline on both subsets (0.538 vs 1.049 all; 0.304 vs 0.413 rolling) but is worse
than LOCO, as expected with fewer analogues. The all-37 LOCO aggregate is dominated by
late-unlock/early-access comparables whose hour-1 is pre-surge (e.g. Silksong ~2120×,
Black Myth Wukong ~92× hour-1); these are deliberately down-weighted for a rolling target
and are not representative of the final case.

**A note on the baseline path:** a prior revision of `Z` had six elements, so
`baselineQuantiles` emitted six values and `scoreCase` skipped every row (`q.length !==
5`), yielding a false `0.000000 / 0.000` baseline. `Z` is now the correct five-element
vector `[-1.645, -0.674, 0, 0.674, 1.645]` and a regression test pins `Z.length === 5`.

## Ablations

Each row changes one thing relative to the shipped v1 defaults (`heatMix=0`,
`platformMix=0`, `logRatioClip=Infinity`, no production date gate). Loss is
lower-is-better.

| Variant | LOCO loss (all) | LOCO loss (rolling) | Temporal loss (all) | Reading |
|---|---:|---:|---:|---|
| **production v1** | **0.395114** | **0.251989** | **0.537588** | shipped choice |
| no regime weighting | 0.394988 | 0.249687 | 0.534131 | marginal; kept for robustness |
| no tier weighting | 0.386611 | 0.264056 | 0.517160 | helps odd launches, hurts target regime |
| no scale similarity | 0.756314 | 0.372936 | 0.857528 | **critical**: tiny pre-surge comparables dominate |
| mean-only centre | 0.410017 | 0.255234 | 0.518181 | robust median blend better on target regime |
| median-only centre | 0.392348 | 0.252994 | 0.558505 | near-tie on LOCO, worse temporally; 0.6 blend kept |
| empirical quantiles | 0.403336 | 0.258089 | 0.569498 | normal-sized band better calibrated (cov 0.908 vs 0.801) |
| band ×0.6 | 0.405271 | 0.247990 | 0.564907 | under-covered (cov 0.734) |
| band ×0.9 | 0.394334 | 0.249248 | 0.541008 | marginally lower loss, lower coverage (cov 0.882) |
| band ×1.2 | 0.401378 | 0.261284 | 0.533616 | slightly over-covered (cov 0.932) |
| band ×1.6 | 0.419336 | 0.290343 | 0.534996 | over-covered / costly (cov 0.959) |

Production keeps the band multiplier at **1.00**: coverage lands at the nominal 0.90 on
the published benchmark, an honest non-overfit choice for a proper scoring rule. The scale
Gaussian bandwidth is `1.2`; removing scale similarity is the single most damaging
ablation.

## Rejected v2 additions (kept only as disabled ablation switches)

These ideas were implemented, measured under both protocols, and **not shipped**. They
remain in the code solely as opt-in switches, all off in `DEFAULT_CONFIG`.

| v2 idea | LOCO loss (all) | Temporal loss (all) | Decision |
|---|---:|---:|---|
| log-ratio clip 1.5 (`v1_plus_clip1.5`) | 0.705747 | 0.845157 | **rejected — clearly harmful** |
| heat mix 0.25 (`v1_plus_heat0.25`) | 0.399612 | 0.536784 | no gain on published LOCO |
| heat mix 0.75 (`v1_plus_heat0.75`) | 0.405980 | 0.535043 | worse on published LOCO |
| platform mix 0.5 (`v1_plus_platform0.5`) | 0.399001 | 0.529898 | marginal; not a demonstrated gain |
| production date gate (`v1_plus_daygate`) | 0.502487 | 0.537588 | **rejected — harms LOCO** |
| all v2 effects on (`v2_as_shipped`) | 0.761956 | 0.846343 | **rejected — regresses both** |

Each heat/platform value is a *slight* change against `0.395114` LOCO — there is **no
demonstrated algorithmic gain** that would justify changing the published model. The
production release-date gate is strictly worse on the published LOCO benchmark; the
temporal protocol applies its own explicit date gate regardless of config, so the
production gate adds nothing there either. `logHeat` remains in the data model as a
**diagnostic field only** and cannot affect the shipped weights (`heatMix = 0` by default);
missing or non-finite diagnostics degrade to a neutral weight factor and can never silently
zero the analogue weights.

## Data leakage policy

- Practice target answers (hours 2–24 of p00–p03) are withheld in the kit and are never
  read, used as training labels, or used to select/tune any parameter.
- LOCO hides the held launch's own curve from its forecast; temporal uses only strictly
  earlier releases. The target's own `logHeat` diagnostic is derived solely from its
  pre-checkpoint history.
- All configuration was chosen on the comparable launches by the leakage-safe protocols
  above; tuning is in-sample.
- No official scorer or reference answers are available locally; no official grade is
  inferred.

an assumption, not a guarantee; the calibrated band is deliberately wide enough to
include such regimes.

## Limitations

- Tuning is in-sample on the 37 comparables; no official practice or final grade is
  available.
- Only 11 clean rolling comparables support the regime-specific numbers — treat them as
  indicative.
- The final uses minute-mean prints, practice uses SullyGnome hourly averages; the
  measures differ.
- The final case will contain the four practice launches as extra comparables; the model
  uses them automatically by regime/tier/scale, but they cannot be validated locally.
- No result here establishes a leaderboard rank, reward competitiveness, or an official
  score.
